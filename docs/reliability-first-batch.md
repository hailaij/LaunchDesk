# 第一批可靠性复现与修复

日期：2026-10-11。基线：v0.5.0；所有配置、日志和进程均为隔离测试资源，未运行真实服务。

## 修复前证据

`artifacts/verification/reliability/before.json`：47 组测试，原有 42 组通过、新增 5 组失败。

| 项目 | 基线结果 | 修复 |
|---|---|---|
| 10 MiB 下限 | 初次写入删除近期小日志 | 按实际轮转大小预留空间，下限不再为零，优先淘汰最旧文件 |
| 占用过期日志 | 删除失败冒泡至 Write，可能停止进程 | 仅清理 IO/权限异常暂缓，保留诊断，后续维护重试 |
| 损坏配置 | JSON 异常直接启动失败 | 最近有效自动/手动备份恢复，保存损坏原件并提示，暂停本次自启 |
| 导出阻塞 | 迭代器持锁时另一线程写入超过 500 ms 未完成 | 捕获文件句柄和长度后释放磁盘锁，读取固定快照 |
| UI 抢磁盘锁 | 磁盘锁占用时 Snapshot 超过 500 ms 未完成 | 磁盘锁与内存显示缓存锁分离 |
| 阻塞 stdin | 原始 v0.5.0 核心输入探针等待 3 秒仍未完成 | 两秒写入上限，终止受管树并等待底层写入释放，不遗留持锁任务 |
| 不运行项的过期日志 | 原始 v0.5.0 核心启动后仍留存 | 启动时与每小时后台维护，无须启动服务；不遍历重解析目录 |
| 日志渲染 | 每次追加更换整份 Document | 复用 Document、64 行小段及缓存行宽；追加不重建历史，段边界对齐时滚动保留原段落，不对齐时重组有限小段但保留行宽缓存 |

配置恢复不会覆盖未来 SchemaVersion，不会因权限/IO 错误擅自回退；全部备份无效时仍保留原件并报错。

## 性能微基准

同机独立 LogView，约 381,190 字符（2,000 行）初次赋值后追加十次：修复前 443 ms，初步修复 191 ms，分段优化后一次测量 112 ms。修复前 `documentReused=false`，修复后为 true。此为未挂到窗口的文本构造微基准，不等于真实 UI 帧时延，也不能证明所有高输出场景都不卡顿。

可见主窗口连续十批、每批 1,000 行输出：一次测量刷新与空闲优先级布局完成耗时 392–601 ms，面板保留 347,828 字符，未超出 500,000 字符边界。该负载仍可能出现短时卡顿，尚未实现日志视图虚拟化。原始结果及截图：`ui-stress-live-log-performance.json`、`ui-stress-stress.png`。

增加布局完成后的自动滚动后，另一轮测量为 439–759 ms；截图确认最后可见行是 `stress-9-999`。记录：`ui-autoscroll-live-log-performance.json`、`ui-autoscroll-stress.png`。没有旧版可见窗口的同条件帧时延对照，因此不声称此负载的帧时延已优于旧版。

原始结果：`artifacts/verification/reliability/ui-before-log-performance.json`、`ui-after-log-performance.json`。另有真实窗口中英文 smoke 截图与回归断言。

## 验证与边界

- `dotnet run --project tests/LaunchDesk.Tests -c Release -- --report artifacts/verification/reliability/after.json`
- 新增清理下限/体积/占用重试、备份恢复/无效备份/未来格式、导出期间写入与删除、UI 缓存锁、空闲清理、输入超时生命周期测试。
- 修复后 53 组核心测试全部通过（包含大块写入和小块 Flush 两种阻塞输入）；构建零警告、零错误，中英文可见窗口与日志压测断言通过。
- UI smoke 验证 Document 与滚动窗口段落复用、分块链接、过滤、暂停、合并、语言切换及正常截图。
- 增量布局完成后再次执行自动滚动，连续输出测试断言面板确实到达最新行，避免使用布局前的旧滚动范围。
- UI 每轮复用一份运行状态快照，日志变化用单调序号，不再对成员 revision 求和。历史加载移至后台。
- 保留同步写入及每块 Flush，避免异步排队改变写失败传播、退出排空和日志完整性；并非已实现异步批量持久化。
- 文件快照仍需短暂磁盘锁捕获，不能消除所有磁盘延迟；被占用文件会临时超过保留目标，释放后再清理。
- 本批不接入签名服务、不新增产品功能、不升级版本、不推送或发布。
