# v0.8.0 Follow-Up: Manager, Service Diagnostics and CLI JSON

Date: 2026-10-12. Baseline: `fb0815bf6dd2ad8135d0e5aa023b5352d5ab6dcb`.
This is a working-tree repair, not a new release or a production service acceptance.

## Reproduction / 逐项复现

### D-1: Manager Switching / 管理器切换

The report's double-catch leak was **not reproduced**. A copy failure rethrows out
of the inner block; it does not enter the subsequent locator catch. A locator
failure also replaces only the already-disposed manager. The existing extracted
settings harness had drifted from current code; it now includes the current
factory, configuration-changing flag and session-journal statements. A source
comparison refuses to run if the transaction differs from production code.

The isolated harness covers destination collision, locator-write failure,
three repetitions of each failure and successful migration. Each completed
attempt leaves exactly one active maintenance task, and final disposal completes
all observed maintenance tasks. No production manager-switch code was changed.
This is not a live settings-dialog/registry test or proof of every disposal fault.

### N-1/N-2: Service Diagnostics / 服务诊断

Before repair, an injected non-elevated status process exiting 7 with stderr
`isolated service failure` displayed only the service-status prefix. Directly
invoking `OnStart` with isolated corrupt configuration or a GUI-disallowed item
threw, but did not create `diagnostics/errors.log`.

The status query now checks exit status, displays stderr (stdout fallback), and
includes the exit code even when both streams are empty. Synchronous startup
exceptions are recorded as `service-start`, set `ExitCode=1`, and are rethrown.
An unwritable diagnostic path must not mask the original policy exception.

The report's claim that elevated actions never show an error was too broad:
the existing `--interactive` host path already displays an error message box.
`UseShellExecute=true`/`runas` cannot use redirected streams. This repair does not
replace that mechanism, bypass UAC, or claim persistent elevated-action diagnostics.

### N-3: CLI JSON Errors / CLI JSON 错误

Before repair, invalid arguments with `--json` produced no JSON on stdout;
deserialization failed with `JsonException`. Transport/timeout catches had the
same plain-text-only code path. JSON preference is now detected before argument
validation. Error results use the existing `ControlResponse` schema on stdout,
with `success=false`, a message, empty items and protocol version 1. Exit codes
1/2/3/4 remain unchanged; non-JSON mode retains stderr diagnostics. Exact help
requests remain human-readable and do not contact the server.
